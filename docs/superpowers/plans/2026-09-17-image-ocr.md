# Image OCR Implementation Plan

**Goal:** Search local clipboard images by their recognized text without changing original clipboard data.
**Architecture:** Rust owns a persistent serial OCR queue, native recognition and SQL search. React renders settings/status and invokes bounded commands.
**Tech Stack:** Tauri/Rust/sqlx/SQLite FTS5, Apple Vision, React/Ant Design.

## Global Constraints
- Default off; images only; original data unchanged; on-device only.
- macOS supported; Windows explicitly unavailable this version.
- Add migration, never edit released migration. Release build uses CARGO_PROFILE_RELEASE_STRIP=none on this macOS 27 host.

## Tasks
- [x] Native recognizer: `src-tauri/src/ocr/native.rs`, native macOS adapter and Cargo dependencies. `supported() -> bool`; `recognize(path: &Path) -> anyhow::Result<String>`. Real generated English/CJK fixture test; bounds and invalid image tests. Keep dependency changes scoped.
- [x] Repository and runtime: `db/ocr.rs`, migration 0002, `ocr/mod.rs`, settings model, command wrappers. Regression test OCR matching before implementing; verify short/long queries, disabled, notes, deletion and clearing. Commands return ImageOcrStatus shape from spec. Single worker, persisted pending rows, unique job tokens protect clear/requeue, late results discarded when disabled/paused.
- [x] Frontend: mirror Ocr settings, command constants/wrappers, preference panel and locales. Backend owns counters/support; UI refreshes status only while panel mounted. Action failures use existing toast wrapper. Settings refresh invalidates clipboard search.
- [x] Integration verification: run typecheck/lint, cargo tests/clippy/fmt, real native fixture OCR; test additive migration on disposable copied data. Review all changes for storage replacement races and loss of user data. Build app and verify isolated dev data before replacing installed version with fresh backup.
